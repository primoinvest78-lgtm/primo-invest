05 — Efeito "3D Premium" (regra fixa do produto)

card-premium & block-navy-3d

Todo modal do site — grande ou pequeno, bege ou azul-marinho — usa uma dessas duas classes compartilhadas. Ambas têm o mesmo efeito embutido: brilho biselado no topo (visível ao passar o mouse) + sombra profunda em múltiplas camadas + brilho ambiente na cor de destaque. Por viverem numa classe central, todo modal novo herda o efeito automaticamente — não é preciso lembrar de aplicar manualmente em cada tela.

Fundo bege + borda verde-menta + brilho no hover.

Uso: cards de conteúdo (KPIs, tabelas, painéis, kanban) — bege com borda verde.

06 — Motion & interação

Padrões de animação

  • Scroll reveal — components/motion/scroll-reveal.tsx: fade + slide-up (16px) ao entrar na tela, via Framer Motion (whileInView, dispara uma vez). Usado em praticamente todo card de conteúdo real.
  • Contador animado — components/ui/animated-number.tsx: números de destaque (patrimônio, KPIs) contam de 0 até o valor real via GSAP (power2.out, ~1.2s) ao carregar a tela.
  • Hover 3D — elevação sutil (-translate-y-0.5 a -translate-y-1) + borda que acende na cor de destaque + sombra mais profunda. Sempre CSS puro (transform/box-shadow), nunca JS, por performance em listas longas.
  • Kanban drag-and-drop — HTML5 nativo (draggable), sem biblioteca externa. Cards entram com stagger leve (delay progressivo por índice) ao carregar a coluna.
  • prefers-reduced-motion — respeitado globalmente via media query que zera duração de transições/animações CSS pra quem tem a preferência ativada no sistema.

07 — Regras de design fixas

Convenções que todo componente novo deve seguir

  • Header grande (nome do módulo) → sempre block-navy-3d, nunca bege.
  • Todo card de conteúdo (pequeno ou grande: tabelas, KPIs, painéis, kanban) → sempre card-premium, nunca branco liso.
  • Texto secundário sobre bege → text-card-beige-muted-foreground, nunca text-muted-foreground padrão (falha contraste AA).
  • Números de destaque → sempre envolvidos em <AnimatedNumber>.
  • Idioma → toda palavra da interface em português, mesmo termos técnicos comuns em inglês (ex: "Suitability" → "Perfil de Investidor").
  • Ações destrutivas (excluir) → sempre com confirmação (window.confirm) antes de executar.

Padrão de dados: toda query em lib/data/*.ts filtra explicitamente por organization_id (defesa em profundidade — a RLS do Postgres já garante isso, mas o filtro explícito evita depender só dela). Toda escrita passa por uma server action em lib/actions/*.ts, nunca direto de dentro de um componente client.

09 — Segurança de dados (RLS)

Multi-tenant por organização

Toda tabela sensível tem uma policy no padrão abaixo — um usuário de uma organização nunca vê dado de outra, reforçado em duas camadas (RLS no banco + filtro explícito no código):

create policy nome_da_tabela_org_access on public.nome_da_tabela
  for all
  using (is_org_member(organization_id))
  with check (is_org_member(organization_id));

-- is_org_member() verifica auth.uid() contra organization_members,
-- exigindo status = 'active'
