05

O efeito “3D premium”

Regra fixa do produto: todo modal — grande ou pequeno — usa uma das duas classes abaixo. Ambas embutem o mesmo comportamento: uma borda de luz acende no topo ao passar o mouse, e a sombra ganha profundidade e um brilho ambiente na cor de destaque. Por viver na classe, todo modal novo herda o efeito sem precisar declarar nada extra.

.card-premium {
  position: relative;
  overflow: hidden;
  background-color: var(--card-beige);
  border: 1px solid color-mix(in oklab, var(--primary) 45%, transparent);
  box-shadow: var(--shadow-panel-3d);
}
.card-premium::before {
  /* barra de luz no topo, invisível até o hover */
  content: "";
  position: absolute;
  inset: 0 0 auto 0;
  height: 3px;
  background: var(--primary);
  opacity: 0;
  transition: opacity 200ms ease;
}
.card-premium:hover::before { opacity: 1; }
06

Motion & interação

  • Scroll reveal — fade + slide-up de 16px ao entrar na tela, via Framer Motion (whileInView, dispara uma vez). Aplicado em praticamente todo card de conteúdo real.
  • Contador animado — números de destaque (patrimônio, KPIs) contam de zero até o valor real via GSAP (power2.out, ~1.2s) ao carregar a tela.
  • Hover 3D — elevação sutil (2–4px) + borda acendendo na cor de destaque + sombra mais profunda. Sempre CSS puro (transform/box-shadow), nunca JS, pra manter listas longas leves.
  • Kanban — drag-and-drop HTML5 nativo, sem biblioteca externa; cards entram com atraso progressivo por índice ao carregar a coluna.
  • prefers-reduced-motion — respeitado globalmente: zera duração de toda transição/animação CSS pra quem ativou a preferência no sistema.
07

Regras que todo componente novo segue

  • Header grande (nome do módulo) → sempre block-navy-3d, nunca bege.
  • Todo card de conteúdo, pequeno ou grande → sempre card-premium, nunca branco liso.
  • Texto secundário sobre bege → text-card-beige-muted-foreground, nunca o tom padrão (falha contraste AA).
  • Números de destaque → sempre dentro de <AnimatedNumber>.
  • Idioma → toda palavra da interface em português, mesmo termos técnicos comuns em inglês.
  • Ações destrutivas → sempre com confirmação explícita antes de executar.
